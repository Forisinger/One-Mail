# 搜索过滤与收信文件夹选择 · 开发计划（v1.3.0）

> 对应 README Roadmap 剩余两项：**邮件搜索与过滤规则** + **收信文件夹选择**。

## 一、目标

1. **搜索与过滤增强**
   - 搜索范围从「主题+发件人」扩展到**正文**，搜索下沉到 SQL（LIKE），不再受前端 200 条截断影响。
   - 新增过滤器：**全部 / 未读 / 有附件** 三个快捷筛选，与账户筛选、搜索关键字可叠加。
   - 结果计数显示在状态栏。

2. **收信文件夹选择**
   - 账户可指定收信文件夹（默认 `INBOX`），如垃圾箱、自定义归档文件夹。
   - 添加/编辑账户对话框支持：手动填写 + **「获取文件夹列表」**按钮（临时 IMAP 连接列出服务器全部文件夹）。
   - 收信客户端按所选文件夹 SELECT/抓取，IDLE 与轮询两种模式均生效。

## 二、技术方案

### 1. 数据库（storage/database.py）
- `mails` 表新增 `folder TEXT DEFAULT 'INBOX'` 列；唯一键从 `(account_id, uid)` 迁移为 `(account_id, folder, uid)`（同一账户不同文件夹的 UID 空间独立）。
- **迁移策略**：启动 `init()` 时检测旧表（无 folder 列），建新表 `mails_v2` → 拷贝数据（folder 置 INBOX）→ 删旧表 → 改名 → 重建索引，全程单事务。
- `insert_mails()` 增加 `folder` 参数；新增 `search_mails(account_id, keyword, unread_only, has_attach, limit)`：关键字对 `subject/from_name/from_addr/body_text` 做 LIKE；返回结果供 UI 直接使用。

### 2. 账户模型（core/account.py）
- `Account` 新增 `folder: str = "INBOX"` 字段（`from_dict` 自动兼容旧配置缺省）。

### 3. 收信客户端（core/mail_client.py）
- 所有 `conn.select("INBOX", ...)` 改为 `conn.select(self.account.folder, ...)`（`_connect` / `_idle_loop` / `_poll_loop` 三处）。
- `_fetch_new` 抓取与入库带上 `folder`。
- 新增静态方法 `list_folders(account, password) -> list[str]`：临时连接 `LIST "" "*"`, 解析带 `\Noselect` 标记的行并跳过，返回可选文件夹名（处理 UTF-7 由服务器返回的原始字节，按 `modified UTF-7` 尽量解码，失败保留原文）。

### 4. 账户对话框（ui/account_dialog.py）
- 新增「收信文件夹」输入行（默认 INBOX）+「获取文件夹列表」按钮：
  - 点击后开子线程连接服务器 LIST；成功则将结果填入下拉 Combobox 供选择；失败则在行内提示错误。
  - 密码取自对话框当前输入框（未填则用已存密码）。

### 5. 主窗口（ui/main_window.py)
- 工具栏搜索框左侧新增过滤器 Combobox：`全部 / 只看未读 / 有附件`。
- `refresh_mails()` 改为调用 `db.search_mails()`；状态栏显示「共 N 封（筛选后 M）」。

### 6. 测试（tests/test_search.py）
- 临时数据库：迁移（旧 schema → 新 schema 数据保留）、folder 去重、search_mails 各条件组合、list_mails 兼容。
- 账户 folder 默认值与 from_dict 兼容。

## 三、不做的事（明确边界）
- 不做服务器端 SEARCH 同步/远程已读同步（保持 readonly 收信，另一计划处理）。
- 不做过滤器规则的持久化保存（本期为快捷筛选；规则引擎视需求另行规划）。
- 不改托盘/通知逻辑。

## 四、验收标准
1. 单元测试全绿（含新增迁移与搜索用例）。
2. 搜索关键字命中正文；「只看未读/有附件」与账户筛选、关键字三者叠加正确。
3. 编辑账户可将收信文件夹改为非 INBOX 并正常收信（IDLE 与轮询路径代码均覆盖，实际收信以 163 INBOX 回归为准）。
4. 打包 exe 正常启动，旧配置/旧数据库无损升级。
