# 增量收信与附件展示 · 开发计划（v1.5.0）

> 来源：审查报告 P2 项中性价比最高的两件事 + 三个杂项修复。

## 一、增量收信（核心）
**问题**：收信用 readonly + BODY.PEEK（语义正确），但服务器端 UNSEEN 永不清零——每个 IDLE 周期/每次推送都把**全部**未读邮件原文重新下载一遍。几百封未读时流量/CPU 浪费严重。

**方案**：
1. 新表 `folder_state(account_id, folder, uidvalidity, max_uid)`，记录每账户每文件夹的 UIDVALIDITY 与已抓取的最大 UID。
2. `_fetch_new`：SEARCH UNSEEN 后，先按 `uid > max_uid` 过滤再 FETCH——SEARCH 很便宜（服务端执行），昂贵的原文下载只发生在新 UID 上，行为语义与现在完全一致（不漏邮件：中断时 max_uid 只记录实际已抓取的最大 UID）。
3. UIDVALIDITY 从 SELECT 的 untagged 响应读取；变化时清空该文件夹的本地缓存并重置 max_uid（UID 复用防错配）。

## 二、阅读区附件名展示
**问题**：DB 只存了 has_attachment 标志，附件名在解析后即丢弃，阅读区无法显示。
**方案**：
1. `mails` 表补 `attachment_names TEXT` 列（init 时 PRAGMA 检查缺失则 ALTER TABLE，兼容旧库）。
2. 入库时存 JSON（parser 已解析出 `attachment_names`）。
3. 阅读区元信息行下方显示「📎 附件：a.pdf、b.zip」。

## 三、杂项修复
1. `tray.run_detached` 包 try/except：无托盘环境（Server Core）不再启动即失败。
2. 托盘角标改用 TrueType 字体（segoeuib.ttf 20px），64px 图标上的数字更大更清晰，失败回退默认字体。
3. `prompt_missing_password` 处理全部缺码账户，不再只弹第一个。
