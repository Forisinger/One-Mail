# OneMail 发邮件功能 · 开发计划

> 版本：v1.1 规划 ｜ 日期：2026-09-29 ｜ 前提：复用现有账户体系与授权码存储

## 一、目标

在一期"多账户收信"基础上，增加**用已配置的邮箱账户发信**的能力：
- 写新邮件、回复收到的邮件
- 支持多个收件人、附件
- 发信过程不卡界面（后台线程）
- 发送后尽力同步到服务器"已发送"文件夹（best-effort，失败不影响发信）

**不做**（记入二期）：草稿箱、抄送/密送界面化（代码预留）、HTML 富文本编辑、定时发送、多签名。

## 二、技术方案

### 1. 账户模型扩展（`core/account.py`）
- `Account` 增加字段：`smtp_host: str = ""`、`smtp_port: int = 465`
- 未显式配置时由 IMAP 主机推导：`imap.xxx.com → smtp.xxx.com`（国内邮箱 465/SSL 通用）
- `from_dict` 按字段过滤，**旧 config.json 无需迁移**

### 2. SMTP 发信引擎（新文件 `core/smtp_client.py`）
- `build_mime(...)`：组装 `MIMEMultipart`——纯文本正文（UTF-8）+ 附件（自动猜 MIME 类型，中文文件名按 RFC 2231 编码）；收件人/主题/发件人头走 `email.header` 规范编码
- `send_mail(account, password, to, subject, body, attachments)`：`SMTP_SSL(host, 465)` → `login` → `send_message`；163 需与 IMAP 同一授权码
- `save_to_sent(...)`：发信成功后另开一条短 IMAP 连接，探测 `已发送 / Sent Messages / Sent` 文件夹并 APPEND；**任何失败静默降级**（163 网页端本身会显示已发送邮件，多数场景服务端自动保存）
- 与收信引擎同等原则：不引入新第三方依赖

### 3. 写信窗口（新文件 `ui/compose_window.py`）
- `Toplevel` 窗体：账户下拉框（仅有授权码的账户）、收件人、主题、正文、附件列表（可增删）
- 「发送」点击 → 按钮/输入框锁定 → **后台线程**执行 SMTP → 完成后回 UI 线程弹结果（`root.after` 投递，杜绝跨线程碰 Tk）
- 支持预填构造：`ComposeWindow(..., account=, to=, subject=, body=)`，供回复用
- 收件人支持逗号/分号/空格分隔多个地址，发送前做格式校验

### 4. 主窗口入口（`ui/main_window.py`）
- 工具栏新增「✉ 写邮件」「↩ 回复」
- 回复：取选中邮件的发件人与账户，预填收件人/主题（`回复：xxx`）/正文引用头

### 5. 测试
- 单元测试 `tests/test_smtp.py`：MIME 组装（多收件人、附件、中文文件名、非 ASCII 头编码）、SMTP 主机推导——**不连网**
- 真实链路：用本机已存授权码，通过用户 163 账户向**其自身地址**发一封测试邮件（主题注明"OneMail 发信功能测试"），验证 SMTP 登录与投递
- GUI 冒烟：写信窗口实例化、回复预填

## 四、风险与对策

- **授权码差异**：163/126 的 IMAP 与 SMTP 共用授权码；个别服务商可能分开——发信失败时提示检查"SMTP 服务是否开启"
- **被拒信**（退信 551/554 等）：把 SMTP 服务器的错误原文透传到界面，方便定位
- **大附件**：不做进度条，但发送期间界面保持可操作，按钮锁定防止重复点
