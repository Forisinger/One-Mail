# 一邮通（OneMail）技术文档

> 版本：v0.1｜日期：2026-09-28｜配套文档：《开发计划.md》

## 一、技术选型

| 模块 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.12 | 指定；生态成熟 |
| 收信协议 | IMAP4（标准库 `imaplib`）+ IMAP IDLE | IDLE 为服务器推送，无需高频轮询，空闲 CPU≈0 |
| 邮件解析 | 标准库 `email` | 无第三方依赖，覆盖 MIME/附件/编码 |
| GUI | tkinter（标准库） | 体积小、无 Qt/Electron 那类百 MB 级依赖，是"占用极小"的关键 |
| 托盘 | pystray + Pillow | 轻量托盘图标与右键菜单 |
| 通知 | win11toast / win10toast（封装 Windows 原生通知） | 原生气泡，不自带 UI 进程 |
| 本地存储 | SQLite（标准库 `sqlite3`） | 单文件、零配置 |
| 密码加密 | Windows DPAPI（`pywin32` 的 `win32crypt`） | 系统级加密，绑定当前用户，无需自管密钥 |
| 自启动 | 注册表 `HKCU\...\Run`（`winreg`，标准库） | 用户级自启，无需管理员权限 |
| 打包 | PyInstaller（--onefile --noconsole） | 单 exe 分发 |

**依赖总量控制**：第三方依赖仅 `pystray`、`Pillow`、`pywin32`、通知库 4 项，其余全用标准库。打包后目标体积 < 30MB，常驻内存 < 50MB。

## 二、系统架构

```
┌─────────────────────────────────────────────┐
│                  OneMail.exe                │
│                                             │
│  ┌─────────┐   事件队列    ┌─────────────┐  │
│  │ UI 层    │◄────────────│  核心引擎     │  │
│  │ tkinter │             │  (core/)     │  │
│  │ 主窗口   │             │              │  │
│  │ 托盘菜单 │             │  AccountMgr  │  │──► config.json (账户/设置)
│  │ 写信窗口 │             │  MailClient  │  │──► onemail.db  (邮件缓存)
│  └─────────┘             │  SmtpClient  │  │
│       ▲                   │  Notifier    │  │
│       │ 通知              └──────┬───────┘  │
│  ┌─────────┐                   │ IMAP/IDLE│
│  │Windows  │                   │ SMTP(465)│
│  │通知中心  │                   ▼          │
│  └─────────┘            [邮箱A] [邮箱B] ...│
└─────────────────────────────────────────────┘
```

**线程模型**（资源占用核心设计）：

- 主线程：tkinter UI + 托盘
- 每个启用的邮箱账户 **1 条守护线程**，内部跑 IMAP IDLE 长连接 —— 服务器有新邮件时主动推，平时阻塞等待，**不消耗 CPU**
- IDLE 每 25 分钟主动刷新一次（RFC 规范），断线自动重连并指数退避
- 不支持 IDLE 的账户（如部分国内服务器）降级为轮询，间隔用户可配（默认 300 秒）

**SQLite 表**：

```sql
-- 邮件缓存（来源标注的核心：account_id 即来源）
CREATE TABLE mails (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    account_id TEXT NOT NULL,       -- 来源账户
    uid TEXT NOT NULL,              -- 文件夹内唯一 ID
    folder TEXT DEFAULT 'INBOX',    -- 收信文件夹（v1.3.0）
    message_id TEXT,
    from_addr TEXT, subject TEXT,
    body_text TEXT,                 -- 提取后的正文
    has_attachment INTEGER DEFAULT 0,
    received_at TEXT, fetched_at TEXT,
    is_read INTEGER DEFAULT 0,
    UNIQUE(account_id, folder, uid)
);
CREATE INDEX idx_mails_account ON mails(account_id, received_at DESC);
```

## 五、关键技术点

### 1. IMAP IDLE 推送（低占用核心）
```
连接 → LOGIN → SELECT INBOX → IDLE
         │                        │
         │◄── 服务器推送 * n 条 EXISTS ──► 触发收信
         │                        │
         └─ DONE → 重新 IDLE（≤25min 循环）
```
- `imaplib` 原生不支持 IDLE，封装：发送 `IDLE` 命令后用 `sock` 层监听非阻塞行读取
- 服务器 25 分钟左右会断，客户端主动 `DONE`→重发 `IDLE` 保活

### 2. SMTP 发信（v1.1 新增，smtp_client.py；v1.2 扩展）
- SMTP 服务器由 IMAP 主机推导（`imap.x.com → smtp.x.com:465`，SSL），也可在账户上显式覆盖 `smtp_host/smtp_port`
- `build_mime()` 纯离线组装：UTF-8 头部走 `email.header` 规范编码；中文附件文件名自动 RFC 2231 编码，收件端可正常还原
- **v1.2**：支持 `cc_addrs/bcc_addrs/html_body`——抄送写入 Cc 头；密送写入 Bcc 头由 `send_message` 自动剥离并并入信封；提供 html_body 时生成 `multipart/alternative`（纯文本兜底 + HTML）
- **v1.2 富文本**：`ui/richtext.py` 逐字符扫描 Text 标签导出 HTML（`<b>/<i>/<u>/<span style>` + 转义 + `<br>`）；字体组合标签模型（b/i/u 七种组合 + 颜色标签独立）规避 Tk 标签优先级竞争
- `send_mail()` 在**后台线程**执行 `SMTP_SSL → login → send_message`，界面全程可响应
- `save_to_sent()` 尽力同步：另开短 IMAP 连接探测"已发送/Sent"文件夹并 APPEND，失败静默降级（163 等服务商网页端会自行保存发件记录）
- 发信失败时把 SMTP 服务器错误原文透传到界面（554/551 等退信原因可直接定位）

### 3. 单实例与窗口唤醒（single_instance.py）
- 命名互斥体 `CreateMutexW` 防双开；第二实例通过命名事件 `SetEvent` 唤醒已运行实例后退出
- 已运行实例收到信号后，主窗口恢复显示并强制置前（临时 topmost 再取消，绕过 Windows 跨应用抢焦点限制）

### 4. 邮件解析（parser.py）
- `email.message_from_bytes` + `EmailMessage.iter_attachments()`
- 编码兜底链：`utf-8 → gbk → gb2312 → latin-1`（国内邮箱大量 GBK）
- HTML 正文用 `html.parser` 剥标签转纯文本，不引入 BeautifulSoup

### 5. 来源标注
- 数据层：每封邮件绑定 `account_id`
- 展示层：邮件列表显示账户名徽标（如 `[QQ工作邮箱]`），左侧栏按账户分组并可单账户筛选
- 通知文案："一邮通 · QQ工作邮箱：新邮件 from 张三"

### 6. 密码安全
- DPAPI `CryptProtectData` 加密后存 `%APPDATA%/OneMail/secrets.bin`
- 解密仅运行时内存中进行；配置文件泄露也不会泄露密码

### 7. 开机自启（autostart.py）
- 键：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
- 值：`"OneMail.exe路径" --minimized`（带参数静默启动到托盘）
- 设置界面提供开关，写/删注册表即可

### 8. 右键复制（v1.1.1 新增）
- 统一走 `_copy_to_clipboard()`：`clipboard_clear/append` + 状态栏"已复制"提示；空值不入剪贴板
- **邮件列表右键**：复制主题 / 发件人姓名 / 发件人邮箱 / 整封正文（命中行才弹菜单）
- **账户面板右键**：复制账户邮箱地址 / 账户名（"全部邮件"卡片不弹）
- **阅读区右键**：复制选中文本 / 全选——标题、元信息、正文任意片段都可选中复制（Text 控件原生能力 + 菜单引导）

### 9. 搜索过滤与收信文件夹（v1.3.0 新增）
- **搜索下沉 SQL**：`search_mails()` 用 LIKE 同时命中主题/发件人姓名/发件人地址/正文，不受前端条数截断影响；与账户筛选、「只看未读/有附件」过滤器任意叠加，返回 (结果, 总数) 供状态栏显示
- **收信文件夹**：账户新增 `folder` 字段（默认 INBOX），`mail_client.py` 三处 SELECT/抓取全部以账户配置为准（IDLE 与轮询路径均覆盖）；数据库唯一键升级为 `(account_id, folder, uid)`（不同文件夹 UID 空间独立）
- **旧库迁移**：`init()` 时检测 mails 表无 `folder` 列则建新表→拷贝数据（folder 记 INBOX）→换名，单事务原子完成，老用户无损升级
- **获取文件夹列表**：账户对话框「获取」按钮开子线程 `LIST "" "*"`，解析 `(flags) delim name` 行、跳过 `\Noselect`，并内置 **IMAP 修改版 UTF-7 解码**（`&XfJT0ZAB-` → 已发送），中文文件夹名正常显示
- **连接管理修正**：`database.py` 改为 contextmanager——提交事务并**真正关闭连接**（原 `with sqlite3.connect()` 只管事务不管关闭，Windows 上会持续占用 db 文件句柄）

### 11. 稳定性加固（v1.4.0 新增，多 Agent 审查产出）
- **防丢数据**：config.json / secrets.bin 原子写（临时文件 + `os.replace`）；配置损坏备份为 `*.corrupt` 再回默认；密码库损坏时中止保存而非清空
- **并发修复**：IDLE 等待改用 `select.select` 分片（不再对 socket settimeout——imaplib 文件对象超时后永久污染，导致每保活周期必重连）；`stop()` 直接关 socket 立即终止线程；「立即收信」通过 `_wake` 事件真正打断等待；`_poll_events` 异常防护防止事件链断裂「失聪」
- **解析健壮性**：未闭合 `<script>/<style>`（CDATA 模式无任何事件）在 `text()` 中取回缓冲区内容，从首个真实排版标记处恢复解析，不再吞掉整封正文
- **匹配边界**：LIKE 转义 `%`/`_`（`ESCAPE '\'`）；`guess_host` 域名精确/子域匹配，`myqq.com` 不再误连 `imap.qq.com`（凭据误发）
- **UI 健壮性**：编辑账户免重输授权码；richtext 按 Tcl 索引推进（emoji 等星形字符不再错位）；对话框线程不触碰 tk 变量、回填判窗口存活；右键菜单用完即毁；发送中关窗确认
- **其他**：IMAP 统一 15s 超时；本地删除邮件（右键/Delete，不动服务器）；发出的邮件补 `Date`/`Message-ID`；搜索 300ms 防抖；save_to_sent 复用 mUTF-7 解码（163「已发送」同步首次真正可用）；单实例互斥体句柄 NULL 不再假阳性；迁移幂等（`DROP TABLE IF EXISTS mails_new` + `BEGIN IMMEDIATE` + 缺列兼容）

### 12. 增量收信与附件展示（v1.5.0 新增）
- **folder_state 表**：按 (account_id, folder) 记录 `UIDVALIDITY` + 已抓取最大 UID；UNSEEN 搜索照旧（服务端执行、开销极小），FETCH 前按 `uid > max_uid` 过滤——readonly+PEEK 下服务器端 UNSEEN 永不清零，此前每个推送/轮询周期都会把全部未读邮件原文重新下载
- **断点续传**：max_uid 只记录实际完成抓取的最大 UID，中断批次下轮自动续抓；UIDVALIDITY 变化（UID 复用）时清空该文件夹缓存重新对账
- **附件名持久化**：mails 表增列 `attachment_names TEXT`（init 时 PRAGMA 检查自动 ALTER），入库存 JSON，阅读区显示「📎 附件：…」
- **杂项**：无托盘环境优雅降级；角标 TrueType 字体（segoeuib 24px，失败回退）；启动时链式提示全部缺码账户
- **v1.5.1 修正**：水位改为入库确认后才推进（收信线程同步入库，只通知真正新邮件；退出前排空事件队列）——堵住「水位先行 + `os._exit` 退出」的丢信窗口；单封 FETCH 失败即断批续抓；文件夹名经 `_folder_wire()` 转回 mUTF-7 并加引号（imaplib 命令按 ascii 编码，中文名/带空格名此前必然失败）；`list_folders` 的 NameError 修复；IDLE 继续行等待有界化并容忍 untagged 行；save_to_sent 用原始 mUTF-7 名 APPEND

### 13. 附件保存与排序（v1.6.0 新增）
- **保存附件**：阅读区右键「保存附件…」——后台线程 `MailClient.fetch_raw()` 按 UID 重新取原文（BODY.PEEK[] 只读不打已读标记），`parser.extract_attachments()` 解析（RFC 2047 文件名解码）后写出，重名加 (n) 后缀；邮件原文不落盘，按需取回
- **列头排序**：点击列头排序（再点反转），UI 侧排序与搜索/过滤器叠加
- `tools/verify_163.py`：真实邮箱端到端验证工具（临时 DB）：连接/UIDVALIDITY/文件夹列表/增量水位/取原文

### 14. 资源占用保障
- 无 Electron、无 Qt、无浏览器内核——tkinter 主进程即全部
- IDLE 阻塞等待 = 空闲 0% CPU；轮询账户 5 分钟一次只是瞬时唤醒
- 邮件正文入库时截断（正文 ≤ 64KB 纯文本），避免数据库膨胀
- 每账户线程 `daemon=True`，退出即回收

### 15. 已读状态同步（v1.7.0 新增，flag_sync.py；v1.8.0 补标记未读入口）
- **职责分离**：收信通道永远 `readonly`（安全红线不变）；改标志走独立**短连接**（连上 → 非readonly SELECT → `UID STORE` → logout），与收信长连接的 socket 状态完全隔离
- **异步成批**：UI 线程只 `submit()` 投递（按 (account, folder, uid, seen) 去重），后台线程每轮合并成批 → 按 (账户, 文件夹, seen) 分组 → UID 数值排序（非数字 UID 剔除防御）→ 每 50 个一批 STORE（`.SILENT` 免 per-uid untagged 回包）——「全部已读」也只占每分组一次连接
- **失败策略**：失败块在组内**内联重试 1 次**（不回队——回队重试可能排到反方向新任务之后，造成服务器端写序与用户意图相反且无自愈）后丢弃并记日志（成功块不重发；已读同步幂等，丢弃无丢失风险）；账户已删/无授权码直接丢弃；`mark_seen` 检查 SELECT 返回值（对不存在文件夹 imaplib 返回 NO 而不抛异常，不拦会把排查引向状态机错误）
- **事务与并发（v1.8.1）**：`mark_all_read_synced` 同事务取未读行+置已读（间隙入库邮件不再漏投递）；`load_password` 持 secrets 锁（防与 save/delete 的 `os.replace` 并发冲突）；编辑账户构造新 `Account` 原子替换（防后台线程读到撕裂的连接参数组合）
- **键泄漏防线**：所有异常路径（凭据读取、前置检查、批处理兜底）都必须释放去重键——宁可少同步一封（幂等可再触发），也不能让键泄漏导致该邮件后续同步请求被永久静默吞掉
- **开关**：托盘勾选项「同步已读到服务器」实时读写 `settings.sync_read_flags`（默认开启；enabled 回调每次现读配置，切换立即生效）；关闭时任务处理前即丢弃，不碰网络
- **标记未读（v1.8.0）**：邮件列表右键「标记为未读」→ 本地 `is_read=0` + flag_sync `seen=False`（`-FLAGS \Seen`）；seen 方向参与去重键，与已读任务互不干扰
- **托盘语义**：托盘「全部标为已读」= 全部账户（与旧版一致）；工具栏按钮尊重当前账户筛选（`mark_all_read(account_id)` 三态参数）
- **可测试性**：`connector` / `get_credentials` / `enabled` 全部构造注入（默认 `MailClient.mark_seen`），`start_thread=False` 可不起线程直测核心分组/切块/重试逻辑；`mark_seen` 另有 imaplib mock 单测覆盖（非 readonly SELECT、.SILENT seq-set、SELECT NO / STORE NO 错误路径、logout）——共 19 项

### 20. OAuth2 登录（v1.10.0，oauth2.py）

- **流程**：授权码 + PKCE(S256) → loopback 回调（127.0.0.1 随机端口，http.server 逐请求处理 + 1s 轮询超时，共 5 分钟）→ 浏览器授权 → 令牌端点换 token。Gmail scope `https://mail.google.com/`；Microsoft 用 `/common/oauth2/v2.0` 端点、scope `offline_access + IMAP.AccessAsUser.All + SMTP.Send`（outlook.office.com 资源，非 Graph）
- **存储**：令牌 JSON（access/refresh/expires_at/provider）经 DPAPI 存 secrets 键 `__oauth2__::<email>`，绝不明文
- **刷新**：`get_access_token` 过期前 120s 触发；模块级锁内「查-刷-存」原子化，scheduler 与 flag_sync 并发到期只刷一次；`invalid_grant` 删坏令牌逼用户重登
- **接入**：`mail_client.imap_login` 统一登录入口（4 处调用点）；SMTP raw `AUTH XOAUTH2`（334 挑战即失败，回空行取消）；Outlook SMTP 587 端口走 STARTTLS（465 仍为 SSL）
- **账户模型**：`auth_type`（password|oauth2）、`client_id`、`client_secret` 字段；scheduler/prompt_missing_password/compose 的「无密码」检查全部放行 OAuth2 账户；删除账户时令牌一并清理
- **UI**：账户对话框认证方式下拉 + Client ID/Secret 输入 + 「浏览器登录」后台线程按钮；OAuth2 时整行联动隐藏密码行

### 21. 邮件图片显示（v1.10.0，imgload.py）

- htmltext 渲染 `<img>` 时插占位符（alt 文本优先）并登记 `(标签名, src)`，render_html 返回清单
- 三类来源：`cid:` 内嵌图（后台 fetch_raw → email 解析 Content-ID → 字节）、`data:` URI（base64 直接解）、远程 http(s)（urllib 下载）
- **安全约束**：仅 http/https；每张 ≤3MB（超限即弃）；每封 ≤10 张；PNG/JPEG/GIF 魔数校验拒绝伪装；下载 10s 超时
- **线程模型**：下载/解析全在后台线程；`to_photo`（Pillow 解码 + 640px 缩宽）与 Text 插入回主线程 `after` 执行；`_img_gen` 代次计数——切走邮件后到达的图片全部丢弃；`_photo_refs` 持引用防 GC
- Pillow 为既有依赖（托盘图标在用），零新增

### 18. 多语言（i18n.py）
- 键名即中文原文的字典方案：`t("立即收信")`——中文零翻译成本，英文表缺键自动回退中文
- `init()` 在 App 构造任何 UI 之前调用；覆盖主窗口/托盘/写信/账户对话框/设置/AI 对话框；core 状态文案在 `set_account_status` 展示时按当前语言映射（整句查表 + 动态文案正则拼装）

### 19. AI 总结 / AI 写信（ai_client.py）
- OpenAI 兼容 `/chat/completions`，纯 `urllib` 实现（零新增依赖）；`build_request` 可离线单测，`chat/summarize/draft` 供后台线程调用，UI 线程绝不碰网络
- 配置：`settings.ai = {base_url, model}` 存 config；API Key 经 `security.save_password("__ai__", key)` 走 DPAPI 加密，绝不明文落盘
- 总结：正文截断 12KB 控制请求体；写信：带可选上下文（回复引用），生成结果经确认替换正文
- 不用流式：总结/写信输出量级小，一次响应更简单可靠

### 20. 本地信件文件夹
- `mails.local_folder`（''=收件箱）与 `folder`（服务器来源文件夹）**严格分离**——附件按需取原文、已读同步都按 (uid, folder) 定位服务器邮件，覆盖 folder 会错位，故移动邮件只改 local_folder
- 文件夹列表存 `settings.local_folders`；账户面板分区显示并带未读徽章；搜索过滤下沉 SQL（`COALESCE(local_folder,'') = ?`）；删除文件夹时邮件自动回收件箱

### 21. 附件打开 / 另存为
- 复用「按需取原文」通道：后台线程 `fetch_raw` → `extract_attachments` → 写 `%TEMP%/OneMail/<mail_id>/` → `os.startfile`；临时文件按邮件复用（已存在不重复下载）
- 「另存为」走 `asksaveasfilename`（默认名=附件名）；文件名沿用 Windows 保留设备名（CON/NUL/...）防御
