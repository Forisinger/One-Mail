# 一邮通（OneMail）技术文档

> 版本：v0.1｜日期：2026-09-28｜配套文档：《开发计划.md》

## 一、技术选型

| 模块 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.12 | 指定；生态成熟 |
| 收信协议 | IMAP4（标准库 `imaplib`）+ IMAP IDLE | IDLE 为服务器推送，无需高频轮询，空闲 CPU≈0 |
| 邮件解析 | 标准库 `email` | 无第三方依赖，覆盖 MIME/附件/编码 |
| GUI | tkinter（标准库） | 体积小、无 Qt/Electron 那类百 MB 级依赖，是"占用极小"的关键 |
| 托盘 | pystray + Pillow | 轻量托盘图标与右键菜单 |
| 通知 | win11toast / win10toast（封装 Windows 原生通知） | 原生气泡，不自带 UI 进程 |
| 本地存储 | SQLite（标准库 `sqlite3`） | 单文件、零配置 |
| 密码加密 | Windows DPAPI（`pywin32` 的 `win32crypt`） | 系统级加密，绑定当前用户，无需自管密钥 |
| 自启动 | 注册表 `HKCU\...\Run`（`winreg`，标准库） | 用户级自启，无需管理员权限 |
| 打包 | PyInstaller（--onefile --noconsole） | 单 exe 分发 |

**依赖总量控制**：第三方依赖仅 `pystray`、`Pillow`、`pywin32`、通知库 4 项，其余全用标准库。打包后目标体积 < 30MB，常驻内存 < 50MB。

## 二、系统架构

```
┌─────────────────────────────────────────────┐
│                  OneMail.exe                │
│                                             │
│  ┌─────────┐   事件队列    ┌─────────────┐  │
│  │ UI 层    │◄────────────│  核心引擎     │  │
│  │ tkinter │             │  (core/)     │  │
│  │ 主窗口   │             │              │  │
│  │ 托盘菜单 │             │  AccountMgr  │  │──► config.json (账户/设置)
│  └─────────┘             │  MailClient  │  │──► onemail.db  (邮件缓存)
│       ▲                   │  Notifier    │  │
│       │ 通知              └──────┬───────┘  │
│  ┌─────────┐                   │ IMAP/IDLE│
│  │Windows  │                   ▼          │
│  │通知中心  │            [邮箱A] [邮箱B] ...│
│  └─────────┘                              │
└─────────────────────────────────────────────┘
```

**线程模型**（资源占用核心设计）：

- 主线程：tkinter UI + 托盘
- 每个启用的邮箱账户 **1 条守护线程**，内部跑 IMAP IDLE 长连接 —— 服务器有新邮件时主动推，平时阻塞等待，**不消耗 CPU**
- IDLE 每 25 分钟主动刷新一次（RFC 规范），断线自动重连并指数退避
- 不支持 IDLE 的账户（如部分国内服务器）降级为轮询，间隔用户可配（默认 300 秒）

```json
    }
  ],
  "settings": {
    "autostart": true,
    "notify_sound": true,
    "check_interval_fallback": 300
  }

```

**SQLite 表**：

```sql
-- 邮件缓存（来源标注的核心：account_id 即来源）
CREATE TABLE mails (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    account_id TEXT NOT NULL,       -- 来源账户
    uid TEXT NOT NULL,              -- 邮箱内唯一 ID
    message_id TEXT,
    from_addr TEXT, subject TEXT,
    body_text TEXT,                 -- 提取后的正文
    has_attachment INTEGER DEFAULT 0,
    received_at TEXT, fetched_at TEXT,
    is_read INTEGER DEFAULT 0,
    UNIQUE(account_id, uid)
);
CREATE INDEX idx_mails_account ON mails(account_id, received_at DESC);
```

## 五、关键技术点

### 1. IMAP IDLE 推送（低占用核心）
```
连接 → LOGIN → SELECT INBOX → IDLE
         │                        │
         │◄── 服务器推送 * n 条 EXISTS ──► 触发收信
         │                        │
         └─ DONE → 重新 IDLE（≤25min 循环）
```
- `imaplib` 原生不支持 IDLE，封装：发送 `IDLE` 命令后用 `sock` 层监听非阻塞行读取
- 服务器 25 分钟左右会断，客户端主动 `DONE`→重发 `IDLE` 保活

### 2. 邮件解析（parser.py）
- `email.message_from_bytes` + `EmailMessage.iter_attachments()`
- 编码兜底链：`utf-8 → gbk → gb2312 → latin-1`（国内邮箱大量 GBK）
- HTML 正文用 `html.parser` 剥标签转纯文本，不引入 BeautifulSoup

### 3. 来源标注
- 数据层：每封邮件绑定 `account_id`
- 展示层：邮件列表显示账户名徽标（如 `[QQ工作邮箱]`），左侧栏按账户分组并可单账户筛选
- 通知文案："一邮通 · QQ工作邮箱：新邮件 from 张三"

### 4. 密码安全
- DPAPI `CryptProtectData` 加密后存 `%APPDATA%/OneMail/secrets.bin`
- 解密仅运行时内存中进行；配置文件泄露也不会泄露密码

### 5. 开机自启（autostart.py）
- 键：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
- 值：`"OneMail.exe路径" --minimized`（带参数静默启动到托盘）
- 设置界面提供开关，写/删注册表即可

### 6. 资源占用保障
- 无 Electron、无 Qt、无浏览器内核——tkinter 主进程即全部
- IDLE 阻塞等待 = 空闲 0% CPU；轮询账户 5 分钟一次只是瞬时唤醒
- 邮件正文入库时截断（正文 ≤ 64KB 纯文本），避免数据库膨胀
- 每账户线程 `daemon=True`，退出即回收

## 八、运行方式（已实现）

```bash
# 专用虚拟环境（tkinter + pystray + Pillow 已就绪）
C:/Users/Administrator/.workbuddy/binaries/python/envs/onemail/Scripts/python.exe src/main.py
# 开机静默启动
... python.exe src/main.py --minimized

# 单元测试
... python.exe tests/test_parser.py
```

数据落盘位置：`%APPDATA%/OneMail/`（config.json 账户配置、secrets.bin DPAPI 加密密码、onemail.db 邮件缓存）。

**运行流程**：启动 → 读配置 → 初始化数据库 → 每个启用账户起一条收信线程（IDLE/轮询）→ 托盘图标 + 主窗口。关窗最小化到托盘，托盘菜单"退出"才真正退出。
