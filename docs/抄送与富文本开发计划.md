# OneMail 抄送/密送与 HTML 富文本 · 开发计划

> 版本：v1.2.0 规划 ｜ 日期：2026-09-29 ｜ 来源：README Roadmap「CC/BCC fields, HTML mail」

## 一、目标

1. **抄送（CC）/密送（BCC）**：写信窗口支持，BCC 收件人互相不可见（标准语义）
2. **HTML 富文本**：正文支持 **加粗 / 斜体 / 下划线 / 字体颜色** 四种基础格式，发送时生成 `multipart/alternative`（纯文本兜底 + HTML 版本），收件端（Outlook/163 网页版等）正常渲染

**不做**（记入后续）：图片内嵌、表格、对齐/字号调节、富文本引用排版。

## 二、技术方案

### 1. MIME 层（`core/smtp_client.py`）
- `build_mime()` 新增可选参数 `cc_addrs / bcc_addrs / html_body`，向后兼容既有调用与单测
- 组装规则：
  - 有 html_body → `multipart/alternative`（plain + html）再套附件层；无则维持现状
  - `Cc` 头写入消息；`Bcc` 头由 `smtplib.send_message` 自动提取进信封并在发出前剥离
- `send_mail()` 同步透传新参数；信封收件人 = To + Cc + Bcc

### 2. 富文本编辑（`ui/compose_window.py`）
- 正文上方加格式工具条：**B / I / U / 颜色 / 清除格式**（tkinter Text 标签实现，零新依赖）
- 字体样式用**组合标签**模型（b/i/u 七种组合 + 颜色标签独立），按字符区间切换，选区撤销/重做继续可用
- 新增模块级函数 `text_to_html(widget)`：逐字符扫描标签 → HTML（转义 + `<b>/<i>/<u>/<span style="color:...">` + `<br>`），可离线单测
- 未使用任何格式时不生成 HTML 分支，退回纯文本邮件（大多数日常邮件场景）

### 3. 写信窗口布局
- 新增抄送/密送输入行；`parse_addresses()` 复用于校验
- 格式工具条置正文区顶部；发送按钮逻辑不变（后台线程）

### 4. 回复兼容
- 回复预填仍是纯文本引用头；用户可对其再套格式（引用部分不自动转 HTML，避免复杂度失控）

## 三、执行顺序

| 步骤 | 内容 | 验证 |
|---|---|---|
| S1 | build_mime/send_mail 扩展（CC/BCC/HTML） | 单测扩展 |
| S2 | text_to_html 导出函数 | 单测（离线） |
| S3 | 写信窗口：CC/BCC 行 + 格式工具条 | GUI 冒烟 |
| S4 | 真实链路：给自己发一封含格式/抄送的邮件 | SMTP 实测 |
| S5 | 打包 exe + 全量回归 | 实测 |
| S6 | 文档同步（技术文档中/英、CHANGELOG、README）+ 推送打 tag | 人工核对 |

## 四、风险与对策

- **组合字体标签冲突**：Tk 标签优先级按创建顺序——采用"每字符唯一字体标签"模型规避
- **颜色对话框跨平台**：仅 Windows 目标，`tkinter.colorchooser` 足够
- **大邮件逐字符导出性能**：万字符级 < 100ms，可接受；超长正文本身就是反模式
- **部分客户端不渲染 HTML**：multipart/alternative 自带纯文本兜底，双保险
