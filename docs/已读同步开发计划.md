# 已读同步开发计划（v1.7.0）

> 2026-09-29。目标：本地标已读后，服务器上的邮件同步置为已读（\Seen），
> 解决"手机/网页端全部显示未读"的割裂感。来源：docs/下一期展望.md 第 1 项。

## 一、背景与现状

- 收信全程 `readonly + BODY.PEEK`，绝不改服务器状态（这是刻意设计，保住了安全底线）。
- 代价：本地标已读（打开邮件 / 标记已读 / 全部已读 / 托盘全部已读）只改本地库，
  服务器仍 UNSEEN。
- 已确认与增量水位不冲突：UNSEEN 收窄只会减少 SEARCH 结果，水位按 UID 推进，互不影响。

## 二、方案设计

### 1. 新模块 `src/core/flag_sync.py`

- `FlagSync` 后台工作线程 + 任务队列 + 去重集合：
  - `submit(account_id, folder, uid, seen=True)` / `submit_many(jobs)`：UI 线程投递，永不阻塞。
  - key = (account_id, folder, uid, seen) 去重，重复提交只处理一次。
  - worker 取批（queue 阻塞取 1 条 + 非阻塞清空队列合并成批，上限 500）→ `_process_batch`。
  - `_process_batch`：按 (account_id, folder, seen) 分组 → 组内 UID 按数值排序 →
    每组按 50 个一批切块 → 逐块调 `connector(account, password, folder, uids, seen)`。
  - 失败重试 1 次（requeue，attempts+1），再失败丢弃并记日志——绝不无限重试。
  - `get_credentials(account_id)` 由外部注入（App 提供 AccountManager 查询）；
    账户已删/无授权码 → 丢弃任务并记日志。
  - `enabled()` 回调注入：读取 config `settings.sync_read_flags`，关闭时任务直接丢弃。
  - `connector` 可注入（默认 `MailClient.mark_seen`）→ 全部核心逻辑可离线单测。
- `MailClient.mark_seen(account, password, folder, uids, seen=True)` staticmethod：
  - 短连接（连上→操作→logout），**非 readonly** `SELECT`，
    `UID STORE <seq-set> (+FLAGS|-FLAGS) (\Seen)`，块大小 50。
  - 复用 `_send_client_id`（163 必须）与 `folder_to_wire`（中文/带空格/& 文件夹名）。

### 2. 配置项

- `settings.sync_read_flags`，默认 `True`（会改服务器状态，须可关，但默认开符合直觉）。

### 3. UI 接线（MainWindow）

- 构造参数新增可选 `flag_sync`（None 时所有同步调用静默跳过，兼容旧调用方/测试）。
- 三处标记已读投递任务：
  - `_on_mail_open`：单封（用行内 `folder`/`uid`，不用 acc.folder——教训同附件保存）。
  - `mark_selected_read`：单封。
  - `mark_all_read`：先 `db.search_mails(..., unread_only=True)` 取未读行 → 批量投递 → 再改库。
- main.py `CMD_MARK_ALL`（托盘"全部标为已读"）：同上，账户范围 = 全部。

### 4. 托盘开关

- 新命令 `CMD_TOGGLE_SYNC`；菜单勾选项"同步已读到服务器"（checked 实时读 config），
  点击由 App 切换并保存，状态栏提示。

### 5. 退出安全

- FlagSync 线程为 daemon；App.quit 本就 `os._exit`，无需特殊清理。
- 已读同步是幂等操作，进程中断最多导致服务器端仍未读（下次标记会再触发），无丢失风险。

## 三、测试计划（tests/test_flag_sync.py，假 connector，不起真线程）

1. 去重：同 key 重复提交只调一次 connector。
2. 分组：跨账户/文件夹的任务按组调用，组内 UID 聚合。
3. 切块：120 个 UID → 50/50/20 三次调用。
4. 重试：connector 首次抛异常 → requeue 重试一次成功；连续两次失败 → 丢弃。
5. 开关关闭：enabled()=False → 不调 connector。
6. 账户缺失：get_credentials 返回 (None, None) → 安全丢弃不崩。
7. UID 数值排序：["10","2"] → 传给 connector 为 ["2","10"]。

## 五、风险与边界

- STORE 只对存在的 UID 生效；UIDVALIDITY 变更后本地 uid 可能失效 → STORE 报错走重试/丢弃，
  无副作用。folder 取行内值（邮件收自哪个文件夹就同步哪个）。
- 部分服务器（如某些企业邮箱）对 STORE 限频：短连接每次标记都新建连接，"全部已读"
  大批量时是**每 (账户,文件夹) 一次连接**（成批合并），不是每封一连，可接受。
- 隐私红线不变：只改 \Seen 标志，不删信、不移动、不改其他标志。
