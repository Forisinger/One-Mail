# 下一期展望（v1.7+ 候选清单）

> 2026-09-29 由多轮审查与开发整理。按性价比排序，动工前先写开发计划。

## 1. 服务器已读状态同步
- 现状：收信全程 readonly + BODY.PEEK，本地标已读后服务器仍 UNSEEN（手机/网页上全部显示未读）。
- 方案：本地标记已读时（_on_mail_open / 标记已读 / 全部已读）投递后台任务，短连接（**非 readonly**）`UID STORE +FLAGS (\Seen)`。
- 注意：会改变服务器状态，属用户可感知行为，建议加设置开关（默认开）；与增量水位不冲突（UNSEEN 收窄只是减少 SEARCH 结果）。

## 2. 邮件 HTML 视图渲染
- 现状：阅读区只显示剥标签后的纯文本。
- 方案：入库时顺带保留 body_html（截断 ≤256KB，剥离 script/style/事件属性）；阅读区用受限渲染（tkinter Text 标签映射 b/i/u/color/link）或内置简单 HTML→Text 标签转换器；附件/图片不内联。
- 注意：绝不执行任何脚本；外部资源不加载。

## 3. 增量收信的 UIDVALIDITY 细化
- 已有基础水位；可补充：把 uidvalidity 纳入去重键或清缓存前提示用户。

## 4. 未读邮件服务端本地一致策略
- 现状：本地"标记未读"不存在（只有已读）；可加右键"标记为未读"（本地 + 可选同步服务器）。

## 5. 多语言（zh-CN / en）
- UI 字符串抽取为资源表；工作量中等，无技术风险。

## 6. OAuth2（Gmail/Outlook）
- 需要 Google/Microsoft 应用注册（client secret 管理与审核），单机分发场景复杂；建议提供"应用密码/授权码 + IMAP"之外的官方 OAuth 桌面流程（PKCE），需用户自建凭据或官方分发。
